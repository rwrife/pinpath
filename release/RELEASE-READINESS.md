## Path to a tag (ordered)

1. Resolve the `U9.2` fanout stub (rev-B rule/pad decision) → DRC 0 errors
   with the stub closed, or accept documented rev-A posture explicitly at a
   fab DFM review.
2. Order boards; inspect received panels against `fab-out/` records.
3. Assemble per `docs/assembly-guide.md`.
4. Execute `docs/bring-up-checklist.md` steps 0–4 with recorded instruments.
5. Execute `docs/characterization-plan.md` M1–M5; update `limits-rev-a.json`
   to validated with new revision.
6. Re-run ERC/DRC/analyzers, firmware and app gates; refresh BOM dates.
7. Only then cut a tag and a release archive with checksums; the app packages
   remain unsigned development artifacts with checksums (signing/notarization
   is a separate later milestone).
